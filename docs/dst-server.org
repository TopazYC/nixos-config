** 路径公式
服务器用三个参数拼出 cluster 路径：
#+begin_example
-persistent_storage_root <ROOT> -conf_dir <CONF> -cluster <NAME>
        →  <ROOT>/<CONF>/<NAME>/
#+end_example
- `-persistent_storage_root`：替代默认的 `~/.klei`。
- `-conf_dir`：替代默认的 `DoNotStarveTogether`。
- `-cluster`：集群名。
本机是 `-persistent_storage_root ~/Game/dst -conf_dir servers -cluster JunXun`，
所以路径是 `~/Game/dst/servers/JunXun/`。*路径对不上最典型的报错就是
`Token file not found ...`。*

** 2. cluster.ini
#+begin_src ini
[GAMEPLAY]
game_mode = survival
max_players = 6
pvp = false
pause_when_empty = true

[NETWORK]
cluster_name = 军训
cluster_description =
cluster_password = 13579
cluster_language = zh
lan_only_cluster = false
offline_cluster = false

[MISC]
console_enabled = true

[SHARD]
shard_enabled = true
bind_ip = 127.0.0.1

#+end_src

- `master_port`：Master 与 Caves 之间的*内部*通信端口，绑在 `127.0.0.1`，
  不用对公网开放。
- `cluster_key`：两个 shard 的握手口令，两个进程读同一个 `cluster.ini`，天然一致。
- `shard_enabled = true` 才会启用洞穴分片。
** 3. Master / Caves 的 server.ini 与端口
*对外端口写在各自 shard 的 server.ini 里*：

#+begin_src ini
# Master/server.ini
[NETWORK]
server_port = 38271

[SHARD]
is_master = true

[ACCOUNT]
encode_user_path = true
#+end_src

#+begin_src ini
# Caves/server.ini
[NETWORK]
server_port = 38272

[SHARD]
is_master = false
name = Caves

[STEAM]
master_server_port = 27017
authentication_port = 8767

[ACCOUNT]
encode_user_path = true
#+end_src

要点：
- `server_port`（UDP）是玩家连进来的游戏端口，Master / Caves 必须不同。
- `[SHARD] is_master` 是区分主/洞的开关。
- `master_server_port` / `authentication_port` 是 Steam 查询/认证端口；
  不写会自动分配，写了就固定，两个 shard 不能撞。
** 4. 防火墙
NixOS 声明式放行 UDP（可用端口见 shard 配置）：

#+begin_src nix
networking.firewall.allowedUDPPorts = [ 38271 38272 ];
#+end_src
- 同网段（192.168.1.0/24）的局域网朋友只需主机放行，不必动路由器。
- 公网直连才需要在路由器做 UDP 端口映射；校园网通常没公网 IP，走 frp。
- frpc 是*主动出站*，不需要在防火墙上开任何入站端口。
** 5. 启动脚本 ~/Game/dst/run_shard.sh
当前脚本（已可用）：
#+begin_src bash
#!/usr/bin/env bash
set -euo pipefail

STEAM="$HOME/.local/share/Steam"
SERVER="$STEAM/steamapps/common/Don't Starve Together Dedicated Server"
SOLDIER="$STEAM/steamapps/common/SteamLinuxRuntime_soldier"
SCOUT="$STEAM/steamapps/common/SteamLinuxRuntime"
BIN="$SERVER/bin64/dontstarve_dedicated_server_nullrenderer_x64"

STORAGE_ROOT="${DST_ROOT:-$HOME/Game/dst}"
CONF_DIR="${DST_CONF_DIR:-servers}"
CLUSTER="${1:?用法: run_shard.sh <集群名> <Master|Caves>}"
SHARD="${2:?}"

CLUSTER_DIR="$STORAGE_ROOT/$CONF_DIR/$CLUSTER"
SHARD_DIR="$CLUSTER_DIR/$SHARD"

list_shards() {
  find "$CLUSTER_DIR" -mindepth 1 -maxdepth 1 -type d -printf '%f\n' 2>/dev/null | sort | tr '\n' ' '
}

# ---- 防呆：分片名拼错时不要默默新建一个空世界 ----
if [ ! -d "$CLUSTER_DIR" ]; then
  echo "错误: 找不到集群目录 $CLUSTER_DIR" >&2
  exit 1
fi
if [ ! -d "$SHARD_DIR" ]; then
  echo "错误: 集群 '$CLUSTER' 下没有分片目录 '$SHARD'" >&2
  echo "可用分片: $(list_shards)" >&2
  exit 1
fi
if ! grep -q '\[SHARD\]' "$SHARD_DIR/server.ini" 2>/dev/null; then
  echo "错误: $SHARD_DIR/server.ini 里没有 [SHARD] 段，看起来不是有效的分片。" >&2
  echo "      常见原因：把分片名拼错了（例如 Caves 写成 Cave），" >&2
  echo "      这样启动会悄悄新建一个空世界，而不是加载你的存档。" >&2
  echo "可用分片: $(list_shards)" >&2
  exit 1
fi
if ! grep -qE '^[[:space:]]*is_master[[:space:]]*=' "$SHARD_DIR/server.ini"; then
  echo "错误: $SHARD_DIR/server.ini 里缺少 is_master 字段" >&2
  exit 1
fi

export SteamAppId=343050 SteamGameId=343050

# 1) steam-run：提供 /usr/bin/true，pressure-vessel 的 bwrap 冒烟测试才能过
# 2) cd bin64：让游戏内部的 ../data 指向安装目录的 data/，否则加载不到 Lua
# 3) 运行时容器提供 libcurl-gnutls.so.4
cd "$SERVER/bin64"

exec steam-run "$SOLDIER/_v2-entry-point" --verb=waitforexitandrun -- \
  "$SCOUT/scout-on-soldier-entry-point-v2" -- \
  "$BIN" \
    -persistent_storage_root "$STORAGE_ROOT" \
    -conf_dir "$CONF_DIR" \
    -cluster "$CLUSTER" \
    -console \
    -shard "$SHARD"
#+end_src
*** 逐行解释
- `set -euo pipefail`：出错即停、未定义变量报错、管道失败也算失败。
- `SERVER`：服务器安装目录；`BIN` 是 64 位主程序。
- `SOLDIER` / `SCOUT`：Steam Linux Runtime 的两层。游戏需要容器里的
  `libcurl-gnutls.so.4` 等库。
- `cd "$SERVER/bin64"`：*关键*。引擎内部会 `chdir("../data")`，
  只有当工作目录是 `bin64/` 时，`../data` 才指向安装目录的 `data/`。
  否则会报 `failed to change working directory to ../data` 并加载不到 Lua。
- `steam-run ...`：*关键*。先进入 Steam 的 FHS 环境，那里有
  `/usr/bin/true`；pressure-vessel 启动前要用 bwrap 跑 `true` 做冒烟测试，
  NixOS 主机本身没有 `/usr/bin/true`，不套这层就会
  `bwrap: execvp true: No such file or directory`。
- `_v2-entry-point --verb=waitforexitandrun -- scout-on-soldier-entry-point-v2 --`：
  和 Steam 启动原生游戏时完全相同的链：host → soldier → scout → 游戏。
- `-console`：开启 stdin 控制台，可以在终端里直接敲 `c_shutdown()` 优雅关服。
  它仍会提示 deprecated（改用 `cluster.ini` 的 `[MISC]/console_enabled`），忽略即可；
  实测只设 `console_enabled = true` 时 stdin 不一定被读取，所以保留这个 flag。
- `-persistent_storage_root / -conf_dir / -cluster / -shard`：见路径公式。
- 开头的 *防呆* 块：分片目录不存在、或 `server.ini` 里没有 `[SHARD]` / `is_master`
  就直接报错并列出可用分片，避免把 `Caves` 拼成 `Cave` 时默默新建一个空世界。

用法（Master / Caves 各开一个终端，或塞进 zellij）：

*** Nushell 版 run_shard.nu

同一件事的 Nushell 实现，放在 =~/Game/dst/run_shard.nu=，用
=nu run_shard.nu JunXun Master= 跑（防呆逻辑与 bash 版一致，两个报错分支已实测）：

#+begin_src nu
#!/usr/bin/env nu
# run_shard.nu — run_shard.sh 的 Nushell 版
# 用法: nu run_shard.nu <集群名> <Master|Caves>

def main [cluster: string, shard: string] {
    let home    = $env.HOME
    let steam   = $"($home)/.local/share/Steam"
    let server  = $"($steam)/steamapps/common/Don't Starve Together Dedicated Server"
    let soldier = $"($steam)/steamapps/common/SteamLinuxRuntime_soldier"
    let scout   = $"($steam)/steamapps/common/SteamLinuxRuntime"
    let bin     = $"($server)/bin64/dontstarve_dedicated_server_nullrenderer_x64"

    let storage_root = ($env.DST_ROOT? | default $"($home)/Game/dst")
    let conf_dir     = ($env.DST_CONF_DIR? | default "servers")
    let cluster_dir  = $"($storage_root)/($conf_dir)/($cluster)"
    let shard_dir    = $"($cluster_dir)/($shard)"

    # ---- 防呆 ----
    if not ($cluster_dir | path exists) {
        error make { msg: $"找不到集群目录 ($cluster_dir)" }
    }
    let available = (
        ls $cluster_dir
        | where type == dir
        | get name
        | each {|p| $p | path basename }
        | str join ' '
    )
    if not ($shard_dir | path exists) {
        error make { msg: $"集群 ($cluster) 下没有分片目录 ($shard)；可用: ($available)" }
    }
    let ini = ($shard_dir | path join "server.ini")
    if not ($ini | path exists) {
        error make { msg: $"缺少 ($ini)" }
    }
    let content = (open $ini)
    if not ($content | str contains '[SHARD]') {
        error make { msg: $"($ini) 里没有 [SHARD] 段（Caves 拼成 Cave？）；可用: ($available)" }
    }
    if not ($content | str contains 'is_master') {
        error make { msg: $"($ini) 里缺少 is_master" }
    }

    $env.SteamAppId  = "343050"
    $env.SteamGameId = "343050"

    # 引擎按 CWD 解析 ../data，必须是 bin64/
    cd $"($server)/bin64"

    let args = [
        $"($soldier)/_v2-entry-point" "--verb=waitforexitandrun" "--"
        $"($scout)/scout-on-soldier-entry-point-v2" "--"
        $bin
        "-persistent_storage_root" $storage_root
        "-conf_dir" $conf_dir
        "-cluster" $cluster
        "-console"
        "-shard" $shard
    ]
    run-external "steam-run" ...$args
}
#+end_src

对照点：
- =X=...= / =$X= → =let x = ...= / =$x=
- =$(...)= → =(...)=
- =[ -d p ]= → =(p | path exists)=
- =grep -q ...= → =($s | str contains ...)=
- =$HOME= → =$env.HOME=；可能没定义的用 =($env.DST_ROOT? | default ...)=
- 最后用 =run-external "steam-run" ...$args= 展开参数列表，省掉 bash 那堆反斜杠续行。

** 6. 64 位 vs 32 位

| | 64 位 | 32 位 |
|---|---|---|
| 二进制 | =bin64/dontstarve_dedicated_server_nullrenderer_x64= | =bin/dontstarve_dedicated_server_nullrenderer= |
| 开法 | 参数完全一样 | 参数完全一样，只换路径 |
| 内存 | 可用 >4GB | 约 4GB 地址空间上限 |
| 适用 | 推荐；mod 多/长期世界必须 | 只适合老 32 位环境 |

官方两个 `launch_dedicated_server.sh` 除了二进制路径外一模一样，而且都依赖
`xterm`（本机没装），不要用。*结论：永远用 `bin64`。*

** 7. 验证

成功时日志里会看到：
- `SteamGameServer_Init success`；
- `Token file not found` 不再出现；
- 监听端口是你 `server.ini` 里写的值（如 38271），而不是 fallback 的 10999；

* 踩坑记录

** 客户端启动失败：Unable to initialize SDL: wayland,x11 not available

- 现象：DST 客户端启动约 2 秒即退出，`console-linux.txt`：
  #+begin_example
  [00:00:00]: WindowManager::Initialize
  [00:00:00]: Unable to initialize SDL: wayland,x11 not available
  [00:00:00]: Error during initialization!
  [00:00:00]: Assert failure 'BREAKPT:' at ../source/dontstarve/application.cpp(1896)
  #+end_example
- 原因：`home/linux/gui/base/desktop-tools.nix` 里全局设了
  =SDL_VIDEODRIVER = "wayland"=，而 DST 自带的
  =bin64/lib64/libSDL2-2.0.so.0= *只编译了 X11 后端*（wayland 相关字符串为 0）。
- 修复：删掉全局 `SDL_VIDEODRIVER`，让 SDL 自己探测；或对单个游戏在
  Steam 启动项写 `SDL_VIDEODRIVER=x11 %command%`。

** 服务器起不来：bwrap: execvp true: No such file or directory

- 现象：`pressure-vessel-wrap[...]: E: Child process exited with code 1:
  bwrap: execvp true: No such file or directory`。
- 原因：`pressure-vessel` 用 bwrap 跑 `true` 做沙箱冒烟测试，而 NixOS 主机的
  =/bin= 只有 =sh=、=/usr/bin= 只有 =env=，没有 `true`。Steam 平时运行在它自己的
  FHS 里，所以不会遇到。
- 修复：用 `steam-run` 包一层（`steam-run` 的 FHS 里有 `/usr/bin/true`）。

** failed to change working directory to ../data

- 原因：工作目录不对。引擎按 CWD 解析 `../data`。
- 修复：启动前 `cd "$SERVER/bin64"`。

** Token file not found

- 现象：日志 `Token file not found: /home/Topaz/Game//servers/JunXun/cluster_token.txt`。
- 原因：`-conf_dir` 与实际目录不一致。当时 token 在
  `~/Game/dst/servers/JunXun`，参数却指向 `~/Game/servers/JunXun`。
- 修复：让三参数拼出的路径与真实目录一致。

** 分片名拼错：Caves 写成 Cave，默默新建空世界

- 现象：`./run_shard.sh JunXun Cave` 之后，`~/Game/dst/servers/JunXun/`
  下多了一个 `Cave/`；日志里出现：
  #+begin_example
  [Shard] Shard server mode disabled: missing is_master setting.
  [Shard] Missing 'is_master' config field.
  Skipping portal[1] (no available shard [Caves] connected)
  #+end_example
- 原因：`-shard` 的名字必须和目录名完全一致。目录不存在时服务器会*
  自动新建*一个只含 `[ACCOUNT]` 的 `server.ini` 和一个空世界，且不报错。
  于是真正的 `Caves/` 没被加载，Master 也找不到洞穴分片，洞穴入口被禁用。
- 影响：真正的 `Caves/` 存档不会被动；但在那个空世界里的进度是无效的。
- 修复：用 `Caves`（有 s）；确认 `Cave/` 是空世界后删掉。
- 防呆：`run_shard.sh` 已内置检查——分片目录不存在、或 `server.ini`

* 路由入门（为什么需要 ip rule / table）

不熟路由表的话先看这节，再看后面的命令会顺很多。

** 路由表（routing table）

内核决定"这个包从哪个网卡、下一跳发给谁"，靠的是一张*路由表*。
默认用的是 =main= 表（编号 254），`ip route` 看到的就是它：

#+begin_example
default via 192.168.1.1  dev enp4s0f3u1u2c2  metric 100
default via 10.35.184.32 dev wlp1s0           metric 600
192.168.1.0/24 dev enp4s0f3u1u2c2 ...
#+end_example

- `default` 是"兜底路由"，没更具体匹配时用它。
- `metric` 越小越优先；所以现在默认走有线。
- `via X` 是下一跳网关；`dev Y` 是从哪个接口出去。
- 除 `main` 外还有 `local`(255)、`default`(253) 和自定义表（1–252）。

** ip rule（策略路由）

默认只查 `main` 一张表。*策略路由*允许"按条件选表"：

#+begin_example
ip rule add uidrange 65534-65534 lookup 100 priority 8000
#+end_example

- `uidrange A-B`：匹配"发出这个包的进程的 uid"。
- `lookup 100`：命中后去查编号 100 的路由表。
- `priority 8000`：规则优先级，*数字越小越先匹配*。
  Clash Verge 的 TUN 规则是 9000+，所以我们用 8000 抢在它前面。

** 一个包怎么选路（简化）

1. 看源地址/目的地址/uid/fwmark 等，按 `ip rule` 从前往后匹配；
2. 命中某条 rule 就查它指定的表；
3. 在表里做最长前缀匹配，选中路由条目；
4. 按条目决定从哪个 `dev` 出去、`via` 哪个网关。

我们的目标就是：让 *frpc 这个进程* 的包命中"表 100"，而表 100 的默认路由是 WiFi。
其它进程不命中，继续走 `main`（有线）。

** 常用查看命令

#+begin_src bash
ip rule show                      # 所有策略规则
ip route show table main          # 默认表
ip route show table 100           # 自定义表
ip route get 1.1.1.1              # 当前进程会怎么走
ip route get 1.1.1.1 uid 65534    # 以 uid 65534 查会怎么走
#+end_src

Nushell（IP 加引号，避免被当数字解析）：
#+begin_src nu
ip rule show                      # 所有策略规则
ip route show table main          # 默认表
ip route show table 100           # 自定义表
ip route get '1.1.1.1'            # 当前进程会怎么走
ip route get '1.1.1.1' uid 65534  # 以 uid 65534 查会怎么走
#+end_src

** 方案 B1：临时用 nobody + 策略路由

# 3) uid 65534 的流量查表 100（priority 8000 抢在 Clash TUN 的 9000 前）
sudo ip rule add uidrange 65534-65534 lookup 100 priority 8000

# 4) 验证

ip route get 1.1.1.1              # 普通进程仍走有线

#+end_src

#+end_src

*** 命令逐条解释

- `nmcli -g IP4.GATEWAY device show wlp1s0`：只取 WiFi 的网关地址。
  动态取是因为 IP/网关会漂（本机 WiFi 就从 10.7.x 变成 10.35.x 过）。
- `ip route replace default via <WG> dev wlp1s0 table 100`：
  在自定义表 100 里写一条默认路由，下一跳是 WiFi 网关，出口是 `wlp1s0`。
  `replace` 而非 `add`，重复执行不报错（幂等）。
- `ip rule add uidrange 65534-65534 lookup 100 priority 8000`：
  新增策略规则——"uid 在 65534~65534 的进程发的包，去查表 100"。
  `priority 8000` 小于 Clash TUN 的 9000，所以优先命中。
- `ip route get 1.1.1.1 uid 65534`：模拟"uid 65534 发往 1.1.1.1"的选路结果，
  用来确认规则是否生效（看到 `dev wlp1s0` 就对了）。
- `sudo -u nobody env HOME=/tmp <frpc> ...`：以 `nobody` 身份运行 frpc，
  这样它的 uid 就是 65534，正好命中上面那条规则。`HOME=/tmp` 是因为
  nobody 的家目录是 `/var/empty`，避免写文件权限问题。
- `ip rule del ...` / `ip route flush table 100`：删除规则、清空自定义表。

为什么用 `nobody`：NixOS 自带 uid 65534，不用新建用户；它平时不跑任何
交互程序，把它的流量整体导到 WiFi 没有副作用。*不要*用你自己的账号
（uid 1000），否则你整个桌面所有联网都会走 WiFi。

** 方案 B2：写进 Nix（专用用户 + oneshot 路由服务）

和 B1 同原理，只是持久化、声明式。给 frpc 一个专用 uid，用一个
oneshot 服务在网络起来后铺好路由表 + ip rule。

#+begin_src nix
{ config, lib, pkgs, ... }:
let
  frpc = /* derivation */;
  frpcUid = 993;
in
{
  users.groups.sakurafrp = { };
  users.users.sakurafrp = {
    isSystemUser = true;
    group = "sakurafrp";
    uid = frpcUid;
  };

  systemd.services.sakura-frp = {
    description = "SakuraFrp frpc client";
    after = [ "network-online.target" "NetworkManager-wait-online.service" ];
    wants = [ "network-online.target" ];
    # 需要常驻就加 wantedBy；只想按需启动就留空
    # wantedBy = [ "multi-user.target" ];
    serviceConfig = {
      User = "sakurafrp";
      ExecStart = "${pkgs.writeShellScript "sakura-frp-start" ''
        exec ${frpc}/bin/frpc \
          -f "$(cat ${config.sops.secrets.sakura_frp_key.path}):<隧道ID1>,<隧道ID2>" \
          -n --disable_log_color
      ''}";
      Restart = "on-failure";
      RestartSec = 5;
    };
  };

  systemd.services.sakura-route = {
    description = "Route sakurafrp traffic over Wi-Fi";
    after = [ "NetworkManager-wait-online.service" ];
    wants = [ "network-online.target" ];
    wantedBy = [ "multi-user.target" ];
    serviceConfig = { Type = "oneshot"; RemainAfterExit = true; };
    path = [ pkgs.iproute2 pkgs.networkmanager ];
    script = ''
      WG=$(nmcli -g IP4.GATEWAY device show wlp1s0)
      [ -n "$WG" ] || exit 1
      ip route replace default via "$WG" dev wlp1s0 table 100
      ip rule del uidrange ${toString frpcUid}-${toString frpcUid} lookup 100 priority 8000 2>/dev/null || true
      ip rule add uidrange ${toString frpcUid}-${toString frpcUid} lookup 100 priority 8000
    '';
  };
}
#+end_src

- 因为 frpc 换成了 `sakurafrp` 用户，sops secret 要么 `owner = "sakurafrp"`，
  要么用 `LoadCredential`。
- `sakura-route` 在每次开机/网络就绪后重铺规则；网关是动态取的，IP 漂了也不怕。
- 不想要常驻就保持 `sakura-frp` 没有 `wantedBy`，用
  `sudo systemctl start sakura-frp` 按需启动。

** bash ↔ Nushell 速查

- 定义变量：=X=...= → =let x = ...=
- 引用：=$X= / =${X}= → =$x=
- 命令替换：=$(cmd)= → =(cmd)=
- 字符串插值：="a $X b"= → =$"a ($x) b"=
- 环境变量：=$HOME= / =$VAR= → =$env.HOME= / =$env.VAR=
- 可选环境变量：=${VAR:-def}= → =($env.VAR? | default 'def')=
- 管道过滤：=... | grep pat= → =... | lines | where ($it =~ 'pat')=
- 目录是否存在：=[ -d p ]= → =(p | path exists)=
- 读文件：=$(cat f)= → =(open f)=
- 字符串包含：=grep -q x f= → =((open f) | str contains 'x')=
- 写文件：=echo x > f= → ='x' | save -f f=
- 变量当命令：=$cmd args= → =^$cmd args=
- 报错退出：=echo err >&2; exit 1= → =error make { msg: 'err' }=
- 函数：=foo() { ... }= → =def foo [] { ... }=
- 路径拼接：="$DIR/$FILE" → =$"($dir)/($file)"=

小坑：
- 整数区间 =65534-65534=、IP =1.1.1.1=、=HOME=/tmp= 这类参数最好加引号，
  否则 nu 可能按表达式解析。
- 外部命令参数里的 =~= 不会展开，要用 =$env.HOME= 或 =$"($env.HOME)/..."=。
- 中间表达式一旦被 nu 命令（=lines=、=where= 等）转成结构化值就不会自动打印，
  需要 =print (...)=；纯外部命令的输出会直接透传。
